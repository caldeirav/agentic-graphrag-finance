# Custom-Judge v1.2.0 Migration Checklist

**Parent**: [016 fair outcome scoring](../spec.md) follow-on  
**Goal**: Raise **graph-full `outcome_accuracy`** from ~0.14 to **0.45–0.60** on the 61-item answer-GT pool while keeping policy **fair** (VA-only outcome, no synthesis fallback) and **non-punitive** (graded `value_alignment`).

**Baseline** (paper-v1.0 checkpoints, bundle v1.1.0, v3 judge):

| Metric | graph-full | Notes |
|--------|------------|-------|
| `outcome_accuracy` | ~0.143 | 61 answer-GT items only |
| Answer-GT pool | 61 / 200 | 48 finagentbench → rubric-only in v1.1.0 |
| MRR = 0 on answer-GT | 45 / 61 (74%) | Primary failure mode |
| Abstention on answer-GT | 39 / 61 (64%) | Mostly PG FinanceBench `domain-relevant` |

Record your baseline before Phase A:


## Policy (do not regress)

- [ ] **Outcome** for answer-GT items = `value_alignment` only (`src/evaluation/judges/outcome_scoring.py`).
- [ ] **No** `synthesis_grounding` fallback for answer-GT headline outcome.
- [ ] **Graded VA** allowed: partial credit for narrative claim coverage and numeric tolerance (Phase C).
- [ ] **Finagentbench comparison** items stay **rubric-only**; report on `rubric_alignment`, not outcome.

**Acceptance**: every narrative answer-GT has `len(required_claims) >= 1`; numeric items have none.

**Acceptance**: `coverage_rate: 1.0`; spot-check 10 PG `domain-relevant` items have ≥3 relevant chunk ids each.

## Phase B — Agent improvements

**Target**: MRR > 0 on ≥50/61 answer-GT items before full repro. **Expected uplift**: +0.20–0.35 on outcome (with Phase C).

### B1. Evidence → synthesis path

- [ ] Fix empty `trajectory_snapshot.evidence_chunks` when `answer.citations` non-empty (`src/evaluation/reproduction/judge_batch.py` hydration, `src/retrieval/synthesis.py` input).
- [ ] Ensure `build_trajectory_from_state` preserves evidence for judge and MLflow (`src/tracing/trajectory_export.py`).

**Acceptance**: integration test — cited answer ⇒ non-empty evidence in snapshot.

### B2. FinanceBench / PG routing (`domain-relevant`)

- [ ] Extend meso/micro routing for segment, business unit, risk category, officer role queries (`src/retrieval/navigation/`).
- [ ] Map keywords: `segment`, `business unit`, `Grooming`, `Braun`, `risk category`, `Item 1`, `Item 1A` → section paths.
- [ ] Verify PG accession `0000080424` graph contains `business_description`, `risk_factors`, segment note chunks.

**Acceptance**: on 5-item PG smoke set, MRR > 0 for ≥4 items (manual or `tests/integration/`).

### B3. Anti-abstention synthesis prompt

- [ ] Update live LLM synthesis prompt in `src/retrieval/synthesis.py` (or prompt template config):
  - If ≥1 on-topic citation: attempt a direct answer.
  - Reserve “cannot identify” / “insufficient evidence” for empty evidence or wrong issuer.
- [ ] Align with judge rubric: abstention when evidence exists should score low `answer_quality`, not reward high `synthesis_grounding`.

**Acceptance**: abstention rate on answer-GT smoke set drops vs baseline (record in PR).

### B4. Qualitative evidence compaction

- [ ] Extend `compact_evidence_for_llm` (`src/retrieval/context_budget.py`) for segment/role/business-structure intents (not only `risk` / MD&A).
- [ ] Increase excerpt budget for Item 1 classification questions if context allows.

### B5. Numeric FinanceBench (`metrics-generated`)

- [ ] Improve XBRL / table-row retrieval for ratio and currency questions (`src/retrieval/navigation/walker.py`, fact extractors).
- [ ] Optional: post-synthesis numeric extraction pass for judge-friendly answers.

**Acceptance**: numeric answer-GT subset (17 items) — MRR > 0 on ≥10 after smoke repro.

### B6. Pre-repro smoke gate

## Phase C — Judge calibration (fair, graded VA)

**Target**: Partial credit where substantively correct. **Expected uplift**: +0.08–0.15.

### C1. `value_alignment` rubric (`configs/judges/gemini_2_5_pro.yaml`)

- [ ] **Numeric**: ±2% relative → 1.0; ±5% → 0.5; normalize `$`, `%`, commas, scale words.
- [ ] **Short label**: 1.0 canonical match; 0.5 clear paraphrase with correct section cite.
- [ ] **Narrative + `required_claims`**: score = supported_claims / total_claims; floor 0.25 if any claim substantively present.
- [ ] **Abstention**: 0.0 when GT expects substance (keep).
- [ ] **Chunk dump**: 0.0 when no question-relevant synthesis (keep).

### C2. Judge panel prompts

- [ ] Ensure `required_claims` injection lists claims clearly (`src/evaluation/judges/gemini_panel.py`).
- [ ] Mock-judge path returns graded VA for calibration tests.

### C3. Judge version bump (if rubric semantics change)

- [ ] If resume skip must invalidate old v3 scores: bump to `v3.1` or `v4` in `gemini_panel.py` + `should_skip_judging`.
- [ ] Document in `contracts/judge-v3-resume.md` or new `judge-v3.1-resume.md`.

### C4. Outcome wiring (unchanged policy)

- [ ] Confirm `compute_outcome_scores` still uses VA-only for answer-GT (`outcome_scoring.py`).
- [ ] No export changes needed if VA is graded 0–1.

### C5. Calibration fixtures

- [ ] Add `tests/fixtures/judge_calibration/` with ~20 items: numeric, short-label, narrative, abstention, chunk-dump.
- [ ] Add `tests/unit/test_value_alignment_calibration.py` — expected VA bands per fixture.
- [ ] Run `judge-batch --force-rescore` on smoke dir after rubric deploy.

**Phase C checkpoint**

```bash
USE_MOCK_JUDGE=1 uv run pytest tests/unit/test_value_alignment_calibration.py tests/unit/test_judge_rubric_prompts.py -q
```
